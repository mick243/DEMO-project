# 매일 18:50 — 작업 진행 상태 점검과 SSOT 갱신

루트 `SSOT.md` 는 "지금 상태" 의 단일 출처다. 손으로 기우다 보면 어디까지가 언제 것인지 알 수 없게 되므로, **하루에 한 번 정해진 시각에 통째로 다시 재서** 맞춘다.

## 언제 하나

- **매일 오후 6시 50분(KST)** 에 한 번.
- 그 시각에 세션이 열려 있으면, 지금 하던 단계를 끊지 말고 마무리한 뒤 바로 이어서 한다. 시작할 때 사용자에게 한 줄로 알린다.
- 그 시각에 세션이 없었다면 **그날 18:50 이후 처음 시작되는 세션**이 대신 한다. 사용자가 다른 일을 시켰다면 그 일을 먼저 끝내고 한다.
- 스케줄 태스크가 이 규칙을 수행하러 띄운 세션이면 곧바로 시작한다.
- **이미 했는지는 `SSOT.md` 첫머리의 `기준 시각` 날짜로 판단한다.** 오늘 날짜면 다시 하지 않는다.

## 1단계 — 진행 상태를 잰다 (문서를 믿지 않는다)

수치는 어느 문서에서도 옮겨 적지 않고 매번 직접 잰다. 아래를 전부 돈다.

1. **커밋** — `git log --all --since="<마지막 기준 시각>" --format="%h %ad %d %s" --date=short`. 이 저장소는 **PR 로만 들어온다**(09-07 이후 master 직접 커밋 없음). 병합 커밋과 그 안의 작업 커밋을 나눠 본다.
2. **원격 동기** — `git rev-list --left-right --count master...origin/master`. 기본 브랜치는 **`master`** 다(`main` 아님). 배포가 원격 master 를 따라가므로 여기가 어긋나면 사이트와 로컬이 다르다. `git pull` · `git push` 는 하지 않는다 — 상태만 적는다.
3. **미커밋** — `git worktree list` 로 **모든 워크트리**를 돌며 `git status --short` 와 오늘 mtime 인 파일을 본다. 미추적 파일도 센다(잔재가 실제로 하나 있었다: `.gitignore.txt`).
4. **브랜치** — 브랜치마다 `git rev-list --left-right --count master...<브랜치>` 로 앞·뒤를 재고 **넷으로** 가른다: 병합 완료 · 병합 대기 · **옛 이력**(09-01 정리 이전 가지 — 앞서 있어도 병합 대상이 아니다) · **백업**(`backup/*`, 지우지 않는다).
5. **콘텐츠 실측** — 이 저장소에는 DB 가 없다. `SSOT.md` 부록 B 의 명령으로 **프로젝트 수 · 갤러리 이미지 수 · 캡션 수 · 라우트 수**를 센다. 갤러리 파일 수와 캡션 수가 어긋나면 화면이 비거나 남는다는 뜻이므로 그때는 §8 에 적는다.
6. **테스트** — **없다.** `package.json` 에 `test` · `lint` 스크립트가 없다. 있는지 매번 확인하고, 생겼으면 돌려서 §7 에 적는다. 빌드는 하지 않는다.

## 2단계 — SSOT.md 를 갱신한다

- **첫머리**: `기준 시각` 을 오늘로 바꾼다. 그 아래 갱신 로그에 `**YYYY-MM-DD 갱신** — 한 줄 요약. §n · §m 반영` 한 줄을 **맨 위에** 더한다. 이전 갱신 줄은 지우지 않는다.
- **매번 다시 재는 절**: §0 30초 요약(세 가지 사실 · 다음 한 걸음) · §2 브랜치와 워크트리 표 · §4 콘텐츠 실측 · §5 기능 현황 · §8 리스크와 미해결 · §9 다음 작업. 나머지 절은 오늘 바뀐 것이 있을 때만 고친다.
- **해결된 항목은 지우지 않는다.** ~~취소선~~ 을 치고 `✅ 해결 YYYY-MM-DD` 와 근거 한 줄을 남긴다.
- **잰 수치만 적는다.** 오늘 재지 못한 수치는 옛 값 옆에 `(YYYY-MM-DD 값 · 미재측)` 을 붙인다.
- 절 번호와 구조는 바꾸지 않는다. 표의 열도 바꾸지 않는다.
- 사이트에 실린 **오락실 파인더 수치는 다른 저장소의 값**이다. 여기서 다시 재려 하지 말고, 출처가 바뀌었는지만 §10 에 적는다.

## 3단계 — 보고하고 커밋한다

- **사용자에게 보고**: ① 오늘 바뀐 것(커밋·PR · 원격 동기 · 미커밋 · 콘텐츠) ② SSOT 어느 절을 어떻게 고쳤나 ③ 사용자 결정이 필요한 것(브랜치 정리 · 백업 처분). 짧게, 표는 하나까지.
- **커밋은 `SSOT.md` 만 담아 하나**로 한다. 메시지는 `SSOT — YYYY-MM-DD 갱신 · <한 줄 요약>`. 다른 변경을 섞지 않는다. **push 는 하지 않는다** — 여기는 공개 저장소이고 push 는 곧 게시다.
- 세션이 워크트리(별 브랜치)에 있으면 그 브랜치에 커밋하고, master 에 넣을지는 보고에 적는다. 주 체크아웃에 있으면 master 에 바로 커밋한다.

## 하지 않는 것

- `git pull` · `git push` · PR 생성 · 브랜치 병합 · 삭제 · 워크트리 정리. 필요하면 §9 에 제안으로만 적는다.
- **`backup/*` 브랜치 삭제.** 정리 전 이력의 유일한 사본이다.
- 빌드 · 배포 · Vercel 조작.
- 스크린샷 다시 찍기. 그건 별도 작업이고 방법은 Claude 메모리 `demo-project-screenshots` 에 있다.
- 문서에 적힌 숫자를 다른 문서로 옮겨 적기. 정본은 콘텐츠 파일과 git 이다.
- 갱신을 미루기 위해 "바뀐 게 없다" 고 단정하기. 바뀐 게 정말 없어도 기준 시각과 갱신 로그 한 줄은 올린다.
